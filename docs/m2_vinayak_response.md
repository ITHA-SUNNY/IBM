# M2 v2 response to data review

1. Separation: v1 was too confounded by new origin/time. v2 samples both independently of class and includes all origin/time combinations per scenario in every generated split. The authored attack pattern combines MFA failure/success, repeated catalog listing, privilege change and repeated high-sensitivity copies. Legitimate behavior overlaps those operations, so no single event proves an attack. This is synthetic ground truth, not verified detection effectiveness.
2. Legit admin NEW_NET: labeled BENIGN, included in training/validation/test/harder/rare. Expected acceptance behavior is no containment solely from origin/time; uncertain cases can alert an analyst. Policy outcomes must be measured after model integration.
3. Event meanings: DATASET_ACCESS plus operation LIST/READ/COPY/WRITE; COMMAND_EXEC plus BATCH_JOB/EMERGENCY_FIX/ROUTINE_STATUS; CRYPTO_OP plus KEY_ROTATE/BULK_ENCRYPT. Same resource vocabulary across classes. See data/event_vocab.md.
4. Official M5 file: data/demo_stream.csv on feature/m2-synthetic-data, after this update. Four sessions/two actors: two BENIGN baseline histories, then one attack and one legit look-alike; admin stays KNOWN_NET. Historical rows are before main events. Use demo_stream_events.csv to exclude ground truth.
5. Legit off-hours: roughly half of each class now starts outside 06:00?21:59 UTC, with overnight batch jobs and emergency fixes. Actual per-scenario new-origin/off-hours counts are in manifest.json. Attacks also occur in office hours and known origins.
6. IDs: U_ plus 12 hex chars, truncated HMAC-SHA256. Synthetic raw IDs: SYNTH_<split>_<index>; demo: SYNTH_demo_attacker/admin. Private key from env or ignored random local key file; prior public key replaced. Same seed/key gives identical output. No real identities or committed secret.
7. Rare attacks: rare_test.csv contains 30 malicious / 1,000 total sessions (3%). Regular development splits now have 40% attacks for class coverage, not production precision claims. Report false positives over benign-session denominator and state prevalence.
8. Actor overlap: verified none across train, validation, test, harder_test, rare_test, demo. Within demo, actors intentionally recur in baseline and main sessions.
9. Harder changes: 4x pacing, multiple noise events, optional failed privilege probes, shuffle of listing observations within discovery. Does not reorder causal stages or claim unseen-family generalization. New-origin benign sessions are now present in all splits.
10. Schema: FAILURE, LOW/MEDIUM/HIGH, off_hours 0/1 implemented. Full data/schema.py was absent from accessible repo branches: please provide branch/file for final validation. Added operation requires M3/M5 acknowledgment; temporary strict 13-column _core.csv copies exist, but full files are preferred.

Important: v2 changes IDs and enums; regenerate/retrain and avoid mixing v1/v2 files. Validation passes 23,788 generated events. No model performance has been measured by M2.
